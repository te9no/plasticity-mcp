# Plasticity MCP 1.0 — Windows / Plasticity 25.3.0

2026-09-09のローカル完成版。37個の専用・高度ツールを提供します。Plasticity全機能の網羅ではなく、以下の対応範囲を検証したリリースです。公式SDKではなく、内部APIを使うバージョン固定アダプターです。

## 導入

リポジトリ直下で `./setup.ps1`。Node.js 22以降が必要です。ビルドとテストを実行し、絶対パス入りの `mcp-client.json` を生成します。IGES変換を追加する場合は `./setup.ps1 -WithIges`。アプリ起動補助は `./start-plasticity.ps1`。編集中のアプリを終了させる処理はありません。

MCPクライアントの起動先に `mcp-server/dist/index.js` を登録します。既に起動中のMCPプロセスは古いコードを保持するため、クライアントから再接続して読み直してください。

## 対応範囲

- 対象ウィンドウの明示指定、形状・階層・名前・材質・表示状態の取得。
- 球・箱・円柱、最大100部品の一括作成、平行移動、回転、非等方スケール。
- ブーリアンの和・差・積、面の押し出し、一定半径フィレット、面・エッジの取得。
- ポリライン、補間スプライン、円、2D寸法拘束レシピの計算と再生成。
- STEP・IGESの入出力、OBJ書き出し。ファイル出力は上書き拒否。
- ネイティブ形式のコピー保存、バックアップ付き文書読み込み。
- 名前変更、グループ作成、材質作成・割り当て、表示切り替え、削除、Undo/Redo。
- 正面・背面・左右・上下・斜めのカメラ、透視／平行投影、全体表示、材質表示、スクリーンショット。
- 明示的な高度ツールとして任意スクリプト実行。

## 復旧・文書保護

書き込み前に `%LOCALAPPDATA%/plasticity-mcp/state` へ復旧記録を同期保存します。`PLASTICITY_STATE_DIR` で変更可能です。通信切断やMCPプロセスの終了をまたいで未確認の操作を検出します。破損した記録は編集を停止させます。

同一レンダラー内で操作記録を共有し、複数MCP接続による同時書き込みを拒否します。文書のクリア／読み込みを検出し、接続時の文書が変わった場合は編集を拒否します。この監視はメモリー上のメソッドを包む方式で、Plasticity本体のファイルは変更しません。

復旧手順: `native_scene` の内容を確認し、その `fingerprint` と `recovery.operationId` を `native_recover` へ渡します。処理が継続中なら拒否します。復旧は処理の再実行ではありません。文書が差し替わっていれば、目的の文書を確認して明示的に `native_connect` し直します。

`native_open_document` は最新のシーン指紋と新規バックアップ先を必須とします。入力ヘッダーを確認し、バックアップ保存後に本体のOpenFileFactoryで読み込みます。失敗時の復元元は指定したバックアップです。

## 実機検証

以下がWindows / Plasticity 25.3.0で成功しました。実機テストは形状を変更するため、検証専用ウィンドウの `PLASTICITY_TARGET` を指定します。

| コマンド | 検証 |
|---|---|
| `npm test` | プロトコル、接続、文書変更、複数クライアント、拘束計算、入力エラー |
| `npm run smoke:native` | MCP stdio経由の作成・変形・差分・OBJ・スクリーンショット |
| `npm run smoke:detail` | トポロジー、押し出し、フィレット、古いエッジの拒否 |
| `npm run smoke:exchange` | 回転・スケール、STEP往復、上書き拒否 |
| `npm run smoke:sketch` | スケッチ、円、スプライン、IGES往復 |
| `npm run smoke:constraints` | 拘束再生成、安定ID、Undo/Redo、矛盾拒否 |
| `npm run smoke:document` | MCP経由の改名、Undo/Redo、コピー保存、上書き拒否 |
| `npm run smoke:parts` | 色・表示・グループ・削除、ネイティブ保存再読込、カメラ範囲 |
| `npm run smoke:recovery` | 遅延応答、再接続、処理中／古い指紋による復旧拒否 |
| `npm run smoke:crash` | MCPワーカープロセスを強制終了後、別プロセスで復旧 |
| `npm run smoke:batch` | 一括作成のUndo、入力全件事前検証、ブーリアン和・積 |

結果ファイルは `artifacts/` に保存されます。

## 総合制作テスト：東京駅

専用MCPツールのみで1,082部品の東京駅外観模型を作成しました。形状のインポートや任意スクリプトによる造形は使っていません。100部品単位の一括作成、材質、変形、ブーリアン、グループ、カメラ、保存を組み合わせ、ネイティブ形式・STEP・OBJへ出力しました。多数部品を扱うツールの上限は4,096 IDです。

完成したネイティブファイルの再読み込みで、1,082部品の名前・材質・親グループを照合しました。曲面は読み込み時に再メッシュ化されるため、表示メッシュ由来の境界は0.05 mmの許容差で比較しています。検証時の最大差は約0.02872 mmでした。生成モデルとローカル検証ログはGit管理対象外です。

材質色の表示には本体同梱の明るいマットキャップを使用し、必要に応じて `native_view` の `edges:false` で細かい部品の輪郭線を消せます。プレビューHTMLはMCP出力のOBJを表示するだけです。

## 明確な境界

- 対応OS／本体バージョン以外の互換性は保証せず、接続時に本体バージョンを検査します。
- 人が同時に行うGUI操作まで排他的に制御しません。任意スクリプトがawaitしない処理や、アプリ内部の直接改変は保証外です。
- 文書指紋は形状ID・バージョン・境界・名前・材質ID・階層・履歴などのスナップショットであり、B-Rep全体の暗号学的チェックサムではありません。
- 任意のロフト／スイープ、すべてのサブオブジェクト編集、完全なインスタンス管理、ネイティブの常時連動拘束は対応範囲外です。
- 結果不明の入出力に使った一時ファイルは、処理中の削除を避けるため残します。
- 上流ライセンスは未指定です。GitHubフォークとして履歴を保持し、独自の再ライセンスは行いません。npm公開は無効です。
